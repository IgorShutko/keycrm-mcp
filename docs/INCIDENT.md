# Инцидент и правила безопасности

## Что произошло 01.11.2026

При параллельном реверс-инжиниринге (эксперименты с payload'ом удаления карточек) в аккаунте `your-account` было удалено 26 реальных карточек воронки. Восстановлены из снимка канбана, сделанного за 26 секунд до удаления: 26 из 26 совпадают со снимком по title, статусу, менеджеру, имени и телефону контакта, комментарию и числу товаров.



## Опасный эндпоинт

```
POST /batch/leads/execute/remove
     ?filters[lead_ids]=<id>
     &column_ids=1,2,3,10,11,12,13
     &pipeline_id=1
```

Если `filters[lead_ids]` не совпал точно (пустой, другой формат, чужой id), сервер удаляет ВСЕ карточки из перечисленных колонок. Это не ошибка клиента, это поведение эндпоинта.

## Правила для этого MCP-сервера

1. Удаление карточек воронки не вынесено в инструменты. `leads(action="remove")` специально возвращает ошибку с объяснением. Карточки удаляются только вручную в KeyCRM UI.
2. `crm_api` блокирует путь `/batch/leads/execute/remove` и любые batch-запросы с параметром `column_ids`.
3. Безопасные удаления, которые можно использовать: `DELETE /tasks/{id}`, `DELETE /clients/{id}`, `POST /batch/orders/execute/remove` с телом `{"ids":[...]}` (проверять, что удаляется ровно нужный id).
4. Любые массовые операции сначала проверять на одном объекте и смотреть, что именно удалилось.
